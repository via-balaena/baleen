Separation kernel · AArch64 / EL2

The assurance map

Baleen keeps two guests apart, and is built so the claim can be checked rather than believed. Two unmodified Linux kernels boot on it and are refused by the hardware when they reach for each other's memory. This page is the honest picture: what is machine-checked, what is only witnessed, and what is not closed at all.

01 — The fence

Half the shipped code is machine-checked. The other half is a thin layer that cannot be.

Verification tools reach code inside the workspace. hv-metal is deliberately excluded — it needs unsafe for MMIO and assembly, so no prover links it and it is held to boot witnesses instead. That one structural fact explains most of the open ledger below.

02 — Evidence by subsystem

Five methods, ten subsystems, and the blanks are the point.

Each method answers a different question. The enumerator checks every reachable state of a small configuration; Kani checks every value at bounded size on real code; Verus carries the unbounded-size step; fuzzing explores wide interleavings; boot witnesses prove the hardware agrees. Nothing is covered by all five, and nothing needs to be — but a gap and a method that structurally cannot reach a subsystem are different claims, so they are drawn differently.

03 — Where the proof effort actually went

The corpus is weighted toward devices and partitioning, not the core state machines.

The core — grants, page types, foreign links — carries few harnesses, because its heavy lifting is done by the enumerator and by Verus. Worth knowing before reading a harness count as uniform coverage.

04 — What is not closed

Grouped by what would actually unblock it, not by severity.

Severity invites argument; "what would move this" invites a decision. Every item is recorded in the repository's ledger with its reasoning — including the ones that were refuted and kept in place so nobody re-pitches them.

Needs hardware

4
  • No silicon. Every metal result is QEMU. A board probe exists and has never run on a board.
  • SMMU translation caching — witnessed on Arm's simulator, not on the boot path.
  • VMID tagging and stage-2 TLBI are not boot-witnessed; QEMU caches nothing, so it structurally cannot show them.
  • The EL2 loader/cache contract — a bring-up assumption, not a checked property.

Needs a different technique

3
  • Scheduler latency bound. A claim about unbounded runs, so no larger bounded harness reaches it — and a safety monitor would budget against exactly this. Scoped, not unknown: Verus has a TLA embedding and Anvil used it to verify controller liveness, on the same Verus already gating this repo.
  • Proportional fairness. A statement about a limit, so not bounded-depth either.
  • The model-to-metal step is a construction argument narrowed by compile-time assertions, because no prover links the metal.

Needs a consumer first

3
  • Grant revocation. Stage-2 is emitted once, so ending a grant does not disturb an emitted descriptor — fine today, a surprise for anything expecting revocation to bite.
  • Monitor freshness. A starved observer cannot tell silence from health; the fix needs a telemetry format that may not be this project's to define.
  • Interrupt-id ceiling — the hardware fence types an interrupt id as one byte, which cannot express the full range. Deferred for want of anything that needs it.
