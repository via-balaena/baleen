7//! # `board-probe` — measure the platform facts `hv-metal` currently assumes
8//!
9//! A standalone bare-metal instrument. **Not** part of the hypervisor, **not** gated by CI, and it
10//! deliberately shares no source with `hv-metal` — the same fence `fvp-probe` keeps, and for the
11//! same reason: an instrument that imports the declarations of the thing it measures is a tautology.
12//!
13//! ## Why this exists BEFORE any port
14//!
15//! `hv-metal` has never run outside QEMU `virt`, and it holds **every platform fact as a `const`** —
16//! it parses no device tree for itself. Porting it means replacing those constants, and each one is
17//! a decision that depends on a number nobody has measured on the target. Design-lesson **#248**:
18//! build the instrument before the code when nothing you run can grade the code. `fvp-probe` did
19//! that for A2 and found a requirement the spec did not have.
20//!
21//! ★ **So this probe answers questions, it does not port anything.** Its output is a list of facts
22//! and, for each, whether it MATCHES what `hv-metal` assumes today. A mismatch is not a failure —
23//! it is the finding, and it is what the port's scope should be built from.
24//!
25//! ## ⚠ The two facts you must supply first, and why they cannot be measured
26//!
27//! * **The load address** — `link.ld`. Nothing can run before the image is where the boot chain
28//!   jumps to.
29//! * **[`UART0_BASE`]** — below. Nothing can be *reported* before there is somewhere to report to.
30//!
31//! Everything else here is read from the hardware. These two are chicken-and-egg and must come from
32//! the board's own documentation. ⚠ **Both default to QEMU `virt`, so the probe self-tests on a
33//! platform whose answers are already known.** An instrument that has never been run where you can
34//! check it is not an instrument — run `qemu-probe.sh` first, every time.
35//!
36//! ## What it must survive
37//!
38//! ⚠⚠ **It must not fault on a board that hands off at EL1.** Reading `SCTLR_EL2` or `ICH_VTR_EL2`
39//! from EL1 traps, and a probe that dies before printing is worse than no probe: you learn nothing
40//! and cannot tell "the board is EL1-only" from "the image never ran". So `CurrentEL` is read
41//! FIRST, on the only path that needs no privilege, and every EL2 register is gated behind it.
42//!
43//! ## Reading the output
44//!
45//! Lines are `@@ <key> = <value>` for raw facts and `@@ VERDICT <name>: <MATCH|DIFFERS|ABSENT> …`
46//! for the comparisons against `hv-metal`'s assumptions. `@@ ` prefixes exist so a transcript can be
47//! grepped out of a noisy boot log — `fvp-probe`'s convention.
48
49use core::arch::{asm, global_asm};
50use core::fmt::Write;
51use core::ptr::{read_volatile, write_volatile};

53// ─── The two supplied facts ─────────────────────────────────────────────────────────────────────
54
55/// **PL011 UART base. ⚠ SUPPLY THIS FROM THE BOARD'S DOCUMENTATION.**
56///
57/// Default is QEMU `virt`'s, which is also what `hv-metal/src/pl011.rs` assumes. Two things can be
58/// wrong on a real board and they fail differently:
59///
60/// * **Wrong address** — silent hang, because there is no UART to report the problem on. This is
61///   why it is the first thing to check when nothing appears.
62/// * **Not a PL011 at all** — many SoCs use 8250/16550-style or vendor UARTs with different
63///   register offsets. [`uart_init`] and [`putc`] below are PL011-specific; a different controller
64///   needs its own two functions, not a different base.
65const UART0_BASE: usize = 0x0900_0000;
66
67/// PL011 register offsets — architectural for the controller, not the board.
68const UART_DR: usize = 0x000;
69/// Flag register; `TXFF` (transmit FIFO full) is bit 5.
70const UART_FR: usize = 0x018;
71/// Line control; must not be written while the UART is enabled.
72const UART_LCR_H: usize = 0x02c;
73/// Control register; `UARTEN` is bit 0, `TXE` is bit 8.
74const UART_CR: usize = 0x030;
75
76// ─── What `hv-metal` assumes today, so each measurement has something to be compared against ────
77//
78// ⚠ These are the ASSUMPTIONS, restated here on purpose rather than imported. The probe shares no
79// source with `hv-metal` (see the module doc), so this list is a deliberate second copy — and if it
80// drifts from the real one, the verdicts below are about a hypervisor that no longer exists. That
81// is the cost of the independence, and it is the right trade only because the list is short and
82// each entry cites where it came from.
83
84/// `hv-metal/src/cache.rs` measures `CTR_EL0.DminLine` and caps it at 64. Measured 64 on QEMU
85/// `virt` AND on Arm's AEM, so a third value has never been seen by this project.
86const ASSUMED_DMIN_LINE: u64 = 64;
87/// `hv-metal/src/gic.rs` reads `ICH_VTR_EL2.ListRegs`; QEMU `virt` reports **4** list registers.
88const ASSUMED_LIST_REGS: u64 = 4;
89/// `ICH_VTR_EL2.PRIbits + 1` — QEMU `virt` reports **5**, i.e. only `ICH_AP0R0_EL2`/`AP1R0_EL2`.
90const ASSUMED_PRI_BITS: u64 = 5;
91/// `hv-metal/src/mmu.rs` pins `TCR_EL2.PS = 0b010` — 40-bit physical addresses.
92const ASSUMED_PA_BITS: u64 = 40;
93/// `hv-metal/src/stage2.rs` uses 8-bit VMIDs (`VTCR_EL2.VS = 0`).
94const ASSUMED_VMID_BITS: u64 = 8;
95
96// ─── Boot ───────────────────────────────────────────────────────────────────────────────────────
97//
98// Park every secondary, set a stack, zero `.bss`, and hand `x0` (whatever the boot chain passed —
99// conventionally a DTB pointer) to Rust. Deliberately the smallest possible startup: this file's
100// job is to survive long enough to print, on a platform where nothing is known.
101
102global_asm!(
103    ".section .text.boot",
104    ".global _start",
105    "_start:",
106    // Preserve the boot chain's x0 — it is data, and on most AArch64 boot protocols it is the DTB.
107    "   mov   x19, x0",
108    // Park secondaries: only the CPU whose MPIDR affinity bits are zero continues.
109    "   mrs   x1, mpidr_el1",
110    "   and   x1, x1, #0xff",
111    "   cbz   x1, 2f",
112    "1: wfe",
113    "   b     1b",
114    "2: ldr   x0, =__stack_top",
115    "   mov   sp, x0",
116    // Zero .bss. The linker aligns both ends to 16, so an 8-byte stride cannot overrun.
117    "   ldr   x0, =__bss_start",
118    "   ldr   x1, =__bss_end",
119    "3: cmp   x0, x1",
120    "   b.hs  4f",
121    "   str   xzr, [x0], #8",
122    "   b     3b",
123    "4: mov   x0, x19",
124    "   bl    probe_main",
125    "5: wfe",
126    "   b     5b",
127);
128
129// ─── UART ───────────────────────────────────────────────────────────────────────────────────────
130
131/// Bring the PL011 up rather than assuming a boot chain left it usable.
132///
133/// ⚠ `fvp-probe` learned this the hard way: it first skipped initialisation on the reasoning that
134/// "the model's UART is already on", which is true of some boot chains and not others. On an
135/// unknown board, assuming is exactly the thing this file exists not to do.
136fn uart_init() {
137    // SAFETY: MMIO writes to a PL011's documented registers at the supplied base. If the base is
138    // wrong this writes to something else — which is unavoidable for a bootstrap fact, and is why
139    // `UART0_BASE`'s doc names a silent hang as the symptom.
140    unsafe {
141        // LCR_H must not be written while enabled, so disable first.
142        write_volatile((UART0_BASE + UART_CR) as *mut u32, 0);
143        // 8-N-1, FIFOs enabled (WLEN=0b11 at bits [6:5], FEN at bit 4).
144        write_volatile((UART0_BASE + UART_LCR_H) as *mut u32, 0b0111_0000);
145        // UARTEN | TXE. No baud programming: the divisor depends on the input clock, which is a
146        // board fact this probe does not know. Every boot chain that produced output before us has
147        // already set it, and the ones that have not will produce garbage rather than silence —
148        // which is itself a readable result.
149        write_volatile((UART0_BASE + UART_CR) as *mut u32, (1 << 8) | 1);
150    }
151}
152
153/// Write one byte, spinning while the transmit FIFO is full.
154fn putc(b: u8) {
155    // SAFETY: as `uart_init`.
156    unsafe {
157        while read_volatile((UART0_BASE + UART_FR) as *const u32) & (1 << 5) != 0 {}
158        write_volatile((UART0_BASE + UART_DR) as *mut u32, u32::from(b));
159    }
160}

162/// A `core::fmt` sink over [`putc`], so the report can use `write!` rather than hand-rolled
163/// formatting — the one place this probe trades size for the ability to print a table.
164struct Uart;
165
166impl Write for Uart {
167    fn write_str(&mut self, s: &str) -> core::fmt::Result {
168        for b in s.bytes() {
169            if b == b'\n' {
170                putc(b'\r');
171            }
172            putc(b);
173        }
174        Ok(())
175    }
176}

178// ─── System-register reads ──────────────────────────────────────────────────────────────────────
179
180/// `CurrentEL[3:2]` — **the only register read on a path that needs no privilege**, and therefore
181/// the first thing done. Everything EL2-specific below is gated on it.
182fn current_el() -> u64 {
183    let v: u64;
184    // SAFETY: `CurrentEL` is readable at every exception level; no memory operand.
185    unsafe { asm!("mrs {v}, CurrentEL", v = out(reg) v, options(nomem, nostack, preserves_flags)) };
186    (v >> 2) & 0b11
187}
188
189/// Read one EL1-readable ID register by name.
190///
191/// A macro rather than a function per register: `mrs` needs the name as an assembly literal, so a
192/// runtime parameter is impossible and the alternative is one near-identical function each.
193macro_rules! read_sysreg {
194    ($name:literal) => {{
195        let v: u64;
196        // SAFETY: a read of an EL1-readable ID/status register. No memory operand, no side effect.
197        unsafe {
198            asm!(concat!("mrs {v}, ", $name), v = out(reg) v, options(nomem, nostack, preserves_flags))
199        };
200        v
201    }};
202}

204// ─── The report ─────────────────────────────────────────────────────────────────────────────────
205
206/// Print a raw fact.
207fn fact(u: &mut Uart, key: &str, value: u64) {
208    let _ = writeln!(u, "@@ {key} = {value:#018x}");
209}
210
211/// Print a verdict: a measured value against what `hv-metal` assumes.
212///
213/// ★ **The verdict is the product, not the raw register.** A hex dump of `ICH_VTR_EL2` tells a
214/// reader nothing about whether the vGIC's context layout survives the port; "DIFFERS (4 assumed,
215/// 6 measured)" tells them exactly which code has to change. Mismatch is **not failure** — it is
216/// the finding this probe exists to produce.
217fn verdict(u: &mut Uart, name: &str, measured: u64, assumed: u64, unit: &str) {
218    let tag = if measured == assumed {
219        "MATCH "
220    } else {
221        "DIFFERS"
222    };
223    let _ = writeln!(
224        u,
225        "@@ VERDICT {name}: {tag} — hv-metal assumes {assumed} {unit}, measured {measured}"
226    );
227}
228
229/// Print a CAPABILITY verdict: does the platform support **at least** what `hv-metal` asks for?
230///
231/// ⚠⚠ **The distinction from [`verdict`] is not cosmetic, and the QEMU self-test is what forced
232/// it.** Three checks here first compared for EQUALITY — PA range, VMID width, granule — and all
233/// three reported DIFFERS on the very platform `hv-metal` was written against, because `-cpu max`
234/// offers 52-bit PAs and 16-bit VMIDs where `hv-metal` *chooses* 40 and 8.
235///
236/// ★ **`hv-metal` picking a smaller value than the hardware offers is not a mismatch, it is a
237/// choice.** What would break a port is a platform that cannot reach the chosen value. So these ask
238/// `measured >= required`, and a platform with room to spare reads SUPPORTS with the headroom
239/// stated — which is also the number you would need if the choice were ever revisited.
240fn capability(u: &mut Uart, name: &str, measured: u64, required: u64, unit: &str) {
241    let tag = if measured >= required {
242        "SUPPORTS"
243    } else {
244        "TOO SMALL"
245    };
246    let _ = writeln!(
247        u,
248        "@@ VERDICT {name}: {tag} — hv-metal needs {required} {unit}, platform offers {measured}"
249    );
250}

252/// **The authoritative list of what this instrument does.** A flat sequence, so reading it costs
253/// about what reading a summary would — and unlike a summary it cannot be wrong (`fvp-probe`'s
254/// module doc records three status paragraphs that rotted before it adopted this rule).
255///
256/// # Safety
257///
258/// Called once from `_start` with the boot chain's `x0`. `extern "C"` so the assembly can call it.
259#[no_mangle]
260pub extern "C" fn probe_main(x0: u64) -> ! {
261    uart_init();
262    let u = &mut Uart;
263
264    let _ = writeln!(u, "\n@@ BOARD-PROBE-BEGIN");
265    let _ = writeln!(
266        u,
267        "@@ note: raw facts are `@@ key = value`; comparisons against hv-metal are `@@ VERDICT`."
268    );
269
270    // ── 1. The gate on everything else. ─────────────────────────────────────────────────────────
271    let el = current_el();
272    let _ = writeln!(u, "@@ CurrentEL = EL{el}");
273    if el != 2 {
274        let _ = writeln!(
275            u,
276            "@@ VERDICT el2: ABSENT — the boot chain handed off at EL{el}, not EL2."
277        );
278        let _ = writeln!(
279            u,
280            "@@ note: baleen is an EL2 hypervisor, so this board cannot host it as configured."
281        );
282        let _ = writeln!(
283            u,
284            "@@ note: check for a firmware option to enter at EL2 before concluding the board cannot."
285        );
286    } else {
287        let _ = writeln!(
288            u,
289            "@@ VERDICT el2: MATCH  — entered at EL2, as hv-metal requires"
290        );
291    }
292
293    // ── 2. Who is this? ─────────────────────────────────────────────────────────────────────────
294    fact(u, "MIDR_EL1", read_sysreg!("midr_el1"));
295    fact(u, "MPIDR_EL1", read_sysreg!("mpidr_el1"));
296    fact(u, "x0_at_entry", x0);
297    let _ = writeln!(
298        u,
299        "@@ note: x0 is conventionally a DTB pointer; 0 means the boot chain passed none."
300    );
301
302    // ── 3. Cache geometry — `hv-metal/src/cache.rs`'s stride. ───────────────────────────────────
303    let ctr = read_sysreg!("ctr_el0");
304    fact(u, "CTR_EL0", ctr);
305    let dmin = 4u64 << ((ctr >> 16) & 0xf);
306    let imin = 4u64 << (ctr & 0xf);
307    let _ = writeln!(u, "@@ CTR_EL0.IminLine bytes = {imin}");
308    verdict(u, "dcache_line", dmin, ASSUMED_DMIN_LINE, "bytes");
309    if dmin < ASSUMED_DMIN_LINE {
310        let _ = writeln!(
311            u,
312            "@@ note: FINER than assumed — cache.rs takes min(64, DminLine), so this is the case it"
313        );
314        let _ = writeln!(
315            u,
316            "@@ note: was written for (#169). A stride WIDER than the true line would skip lines."
317        );
318    }
319
320    // ── 4. Address translation limits — mmu.rs and stage2.rs pin these. ─────────────────────────
321    let mmfr0 = read_sysreg!("id_aa64mmfr0_el1");
322    fact(u, "ID_AA64MMFR0_EL1", mmfr0);
323    // PARange is bits [3:0]; the encoding is a table, not a formula.
324    let pa_bits = match mmfr0 & 0xf {
325        0 => 32,
326        1 => 36,
327        2 => 40,
328        3 => 42,
329        4 => 44,
330        5 => 48,
331        6 => 52,
332        _ => 0,
333    };
334    capability(u, "pa_range", pa_bits, ASSUMED_PA_BITS, "bits");
335    if pa_bits < ASSUMED_PA_BITS && pa_bits != 0 {
336        let _ = writeln!(
337            u,
338            "@@ note: SMALLER than assumed — mmu.rs pins TCR_EL2.PS=0b010 (40-bit) and would be"
339        );
340        let _ = writeln!(
341            u,
342            "@@ note: naming a physical address size this core cannot encode."
343        );
344    }
345    // `TGran4` is bits [31:28]. ⚠ It is a SUPPORT code, not a size: `0b0000` = 4 KiB supported,
346    // `0b0001` = supported *including* 52-bit output addresses, `0b1111` = NOT supported. The first
347    // draft here tested `== 0` and reported DIFFERS on QEMU `-cpu max`, which answers `0b0001` — a
348    // MORE capable core failing a check meant to catch a less capable one.
349    let tgran4 = (mmfr0 >> 28) & 0xf;
350    let tgran4_ok = tgran4 != 0b1111;
351    let _ = writeln!(
352        u,
353        "@@ VERDICT granule_4k: {} — hv-metal emits only 4 KiB (TGran4 = {tgran4:#x})",
354        if tgran4_ok { "SUPPORTS" } else { "TOO SMALL" }
355    );
356
357    let mmfr1 = read_sysreg!("id_aa64mmfr1_el1");
358    fact(u, "ID_AA64MMFR1_EL1", mmfr1);
359    // VMIDBits is bits [7:4]: 0b0000 = 8 bits, 0b0010 = 16 bits.
360    let vmid_bits = if (mmfr1 >> 4) & 0xf == 2 { 16 } else { 8 };
361    capability(u, "vmid_bits", vmid_bits, ASSUMED_VMID_BITS, "bits");
362
363    // ── 5. The vGIC's shape — gic.rs reads this, and the context layout follows from it. ────────
364    if el == 2 {
365        let vtr = read_sysreg!("ich_vtr_el2");
366        fact(u, "ICH_VTR_EL2", vtr);
367        verdict(
368            u,
369            "list_registers",
370            (vtr & 0x1f) + 1,
371            ASSUMED_LIST_REGS,
372            "LRs",
373        );
374        verdict(
375            u,
376            "priority_bits",
377            ((vtr >> 29) & 0x7) + 1,
378            ASSUMED_PRI_BITS,
379            "bits",
380        );
381    } else {
382        let _ = writeln!(
383            u,
384            "@@ VERDICT list_registers: ABSENT — ICH_VTR_EL2 needs EL2; not read"
385        );
386    }
387
388    // ── 6. SCTLR_EL2's RESET value — the RES1 question. ─────────────────────────────────────────
389    if el == 2 {
390        let sctlr = read_sysreg!("sctlr_el2");
391        fact(u, "SCTLR_EL2_at_reset", sctlr);
392        let _ = writeln!(
393            u,
394            "@@ VERDICT sctlr_res1: {} — QEMU reports a flat 0x0; silicon should read RES1 bits back as 1",
395            if sctlr == 0 { "MATCH " } else { "DIFFERS" }
396        );
397        let _ = writeln!(
398            u,
399            "@@ note: a non-zero value here is EXPECTED and is good news — it is the case mmu.rs's"
400        );
401        let _ = writeln!(
402            u,
403            "@@ note: read-modify-write of SCTLR_EL2 was written for and has never met."
404        );
405    }
406
407    // ── 7. The timer — time.rs treats CNTFRQ_EL0 as advisory. ───────────────────────────────────
408    fact(u, "CNTFRQ_EL0", read_sysreg!("cntfrq_el0"));
409    let _ = writeln!(
410        u,
411        "@@ note: CNTFRQ_EL0 is firmware-programmed and documented as advisory; a wrong value gives"
412    );
413    let _ = writeln!(
414        u,
415        "@@ note: a slice of the wrong duration, not a lost guarantee."
416    );
417
418    let _ = writeln!(u, "@@ BOARD-PROBE-END");
419    loop {
420        // SAFETY: a hint instruction; no memory operand, no privilege requirement.
421        unsafe { asm!("wfe", options(nomem, nostack, preserves_flags)) };
422    }
423}

425/// Halt quietly. There is nothing to report a panic *to* that is more reliable than the UART this
426/// probe may have failed to bring up, so it does not try.
427#[panic_handler]
428fn panic(_: &core::panic::PanicInfo) -> ! {
429    loop {
430        // SAFETY: as `probe_main`'s park loop.
431        unsafe { asm!("wfe", options(nomem, nostack, preserves_flags)) };
432    }
